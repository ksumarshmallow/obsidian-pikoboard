# PikoBoard

Минималистичная тёмная доска для Obsidian: задачи по статусам, материалы рядом с задачей и следующий шаг всегда под рукой. Каждая задача остаётся обычным Markdown-файлом.

**Самостоятельный плагин: TaskNotes, Kanban, Dataview и другие сторонние плагины не нужны.** Проверено на macOS в Obsidian 1.14.4. Интерфейс пока на русском, названия столбцов — на английском.

## Что умеет

- Три столбца: **backlog → in progress → done**, перетаскивание между ними и ручной порядок внутри столбца.
- Обычный и компактный канбан, фильтры по проекту и тегам; отдельный обзор всех задач в работе.
- Название обязательно; проект, срок и теги — по желанию. Один проект на задачу.
- Описание с форматированием, чеклистами, ссылками и вложениями; автоматическое сохранение.
- Комментарии прямо на доске и в окне задачи, свежие сверху. Их можно копировать, редактировать и удалять с подтверждением.
- Закреплённый следующий шаг: текст или интерактивный чеклист. Галочки не завершают задачу и не создают записи в истории.
- Материалы: ссылка на существующую заметку, новое исследование или файл с компьютера.
- Архив, восстановление удалённых комментариев и защита от перезаписи текста при конфликте изменений.

## Установка

### Клоном репозитория

Закройте хранилище или откройте другое на время установки. В терминале из корневой папки нужного хранилища выполните:

```sh
git clone https://gitlab.com/ksumarshmallow/obsidian-pikoboard.git .obsidian/plugins/personal-board
```

Затем откройте хранилище в Obsidian → **Настройки → Сторонние плагины → обновить список** и включите **PikoBoard**. Если имя не обновилось, перезапустите Obsidian. Откройте доску через значок в левой панели или команду **PikoBoard: Открыть доску дел**.

Имя папки `personal-board` должно совпадать с `id` в `manifest.json`. Клон в произвольную папку компьютера не устанавливает плагин в Obsidian. Если у хранилища другая папка конфигурации, замените `.obsidian` в команде на неё. Автоматически включать сторонние плагины за пользователя Obsidian не позволяет.

Готовый `main.js` лежит в репозитории: `npm install` и сборка для установки не нужны. Плагин появится в списке **установленных** плагинов; в общем каталоге сообщества его пока нет.

### Без Git

Скачайте репозиторий через **Code → Download source code → zip**, распакуйте и скопируйте **`main.js`, `manifest.json`, `styles.css`, `LICENSE`, `THIRD-PARTY-LICENSES.txt`** в `.obsidian/plugins/personal-board/` внутри своего хранилища. Затем обновите список сторонних плагинов и включите PikoBoard.

### Обновление и переход с прежней версии

Закройте окна задач и выключите PikoBoard. В клонированной папке выполните `git pull --ff-only` или замените пять файлов вручную, затем включите плагин снова. Если папка уже существует после ручной установки, не клонируйте поверх неё: используйте ручное обновление.

Технический ID `personal-board` сохранён для совместимости с ранними локальными версиями. **Не заменяйте `data.json`**: там порядок карточек, черновики, настройки и корзина комментариев.

При первом запуске версии 0.7 PikoBoard однократно читает настройки хранения установленного TaskNotes, если они есть: папку задач, служебный тег или свойство, имена полей и сроки архивации. Личные заметки при этом не переписываются. После этого TaskNotes можно выключить; его код не используется. Старые описания, комментарии, материалы и следующие шаги остаются совместимыми.

Папка новых задач и автоархивация доступны в **Настройки → PikoBoard**. Изменение папки влияет только на новые задачи. В новом хранилище папка по умолчанию — `Задачи`, автоархивация — через 7 дней.

## Как пользоваться

**+ Задача** открывает строку сверху столбца. Enter создаёт задачу; Cmd/Ctrl+Enter создаёт её и открывает окно. Если выбран проект, новая задача наследует его. Название открывает задачу; стрелка справа раскрывает историю на доске.

**Запись** добавляет комментарий: Enter отправляет, Shift+Enter переносит строку. Скрепка прикрепляет материалы. Меню `⋯` позволяет изменить или удалить запись; восстановление доступно сразу после удаления и через команду **PikoBoard: Восстановить удалённую запись**.

**Следующий шаг** заменяет текущий закреплённый текст. Карандаш подставляет его в поле редактирования, крестик снимает закрепление с возможностью отмены. Кнопка **Чеклист** добавляет пункт; Enter продолжает список, Enter на пустом пункте завершает список, Cmd/Ctrl+Enter сохраняет. Отмеченные пункты остаются на месте. Результат работы можно отдельно записать в историю.

**Проекты** определяются свойством `type: project` в заметке. Новые проекты создаются в `Проекты/`, исследования — в `Материалы/`, прикреплённые файлы — в `Вложения/`. Теги вводятся прямо в карточке: `#пример #ресерч`.

**Архив** скрывает задачу с основной доски, сохраняя файл. PikoBoard проверяет завершённые задачи при открытии хранилища и раз в минуту, пока Obsidian работает. По умолчанию они уходят в архив через 7 дней; срок можно изменить или отключить в настройках. Если Obsidian был закрыт, архивация произойдёт при следующем открытии. Возврат завершённой задачи из архива даёт новый полный срок до архивации. Корзина задачи перемещает её файл в `.trash` хранилища после подтверждения.

## Данные и приватность

Задачи, описания, история и следующий шаг хранятся в файлах текущего хранилища. Порядок карточек, черновики и удалённые комментарии — в `.obsidian/plugins/personal-board/data.json`. История и шаг отделены служебными HTML-комментариями: не удаляйте эти маркеры вручную.

В PikoBoard нет собственной аналитики, ключей доступа или кода отправки заметок на сервер. Синхронизация определяется настройками Obsidian; внешние ссылки и вложенные ресурсы обрабатываются его Markdown-рендерером и другими установленными плагинами.

Этот репозиторий содержит только код, документацию и искусственные тестовые данные. Файлы хранилища, резервные копии, локальные настройки и импорты в него не входят. Не прикладывайте `data.json`, реальные заметки или скриншоты с личными данными к публичным issues.

## Разработка

Требуется Node.js 18+. Для сборки и тестов нет npm-зависимостей, `npm install` не нужен.

```sh
git clone https://gitlab.com/ksumarshmallow/obsidian-pikoboard.git
cd obsidian-pikoboard
npm test
npm run check
```

- `plugin.js` — интерфейс, настройки и интеграция с Obsidian.
- `task-store.js` — самостоятельное чтение и атомарная запись задач, совместимость прежних полей и автоархивация.
- `core.js` — работа с Markdown, история, следующий шаг, фильтры и порядок.
- `styles.css` — оформление.
- `build.js` — сборка `main.js`; готовый файл не редактируется вручную.
- `tests/` — автоматические тесты хранения, миграции, архивации, конфликтов сохранения и синхронизации ввода.

После изменения кода выполните `npm test`: команда сначала пересоберёт `main.js`. Для проверки интерфейса используйте отдельное тестовое хранилище.

## Ограничения

- PikoBoard читает задачи с тегом `task` в свойствах заметки; при переходе сохраняет настроенный в TaskNotes способ определения задач. Файлы обычных заметок и проектов не становятся задачами автоматически.
- Календари, тайм-трекинг, повторяющиеся задачи и представления Bases из TaskNotes здесь не реализованы. Существующие дополнительные поля сохраняются, но PikoBoard не выполняет связанную с ними логику.
- Три столбца фиксированы. Блокирующих зависимостей между задачами и совместного редактирования в реальном времени нет.
- Редактор описания использует внутренний API Obsidian и может потребовать адаптации после обновления приложения. Если загрузить его не удалось, остаётся обычное текстовое поле.
- Интерфейс адаптируется к узкому окну, но на телефоне отдельно не проверен.
- Это ранняя версия. Перед обновлением полезно иметь резервную копию хранилища.
