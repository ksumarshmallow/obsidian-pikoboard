# PikoBoard

Минималистичная тёмная доска для Obsidian: задачи по статусам, материалы рядом с задачей и следующий шаг всегда под рукой. Каждая задача остаётся обычным Markdown-файлом.

**Самостоятельный плагин: TaskNotes, Kanban, Dataview и другие сторонние плагины не нужны.** Проверено на macOS в Obsidian 1.14.4. Интерфейс пока на русском, названия столбцов — на английском.

## Что умеет

- Именованные доски в любой папке хранилища. Каждая доска — файл `.pikoboard`, задачи — отдельные `.md`.
- По умолчанию **backlog → in progress → done**. Можно добавлять, переименовывать и переставлять столбцы, менять цвет, насыщенность фона, иконку или эмодзи, убирать значок.
- Один компактный канбан, фильтры по проекту и тегам, архив и общий обзор всех досок. «В работе» фильтрует задачи, сохраняя столбцы.
- Настраиваемые папки досок, задач, вложений, исследований и проектов. Для задач и вложений отдельной доски можно задать свои папки.
- Название обязательно; проект, срок и теги — по желанию. Один проект на задачу.
- Описание с форматированием, чеклистами, ссылками и вложениями; автоматическое сохранение.
- Комментарии прямо на доске и в окне задачи, свежие сверху. Их можно копировать, редактировать и удалять с подтверждением.
- Закреплённый следующий шаг: текст или интерактивный чеклист. Галочки не завершают задачу и не создают записи в истории.
- Материалы: ссылка на существующую заметку, новое исследование или файл с компьютера.
- Архив, восстановление удалённых комментариев и защита от перезаписи текста при конфликте изменений.

## Установка

### Клоном репозитория

Закройте хранилище или откройте другое на время установки. В терминале из корневой папки нужного хранилища выполните:

```sh
git clone https://gitlab.com/ksumarshmallow/obsidian-pikoboard.git .obsidian/plugins/pikoboard
```

После клонирования:

1. Откройте хранилище в Obsidian → **Настройки → Сторонние плагины**. Если включён ограниченный режим, разрешите сторонние плагины.
2. Нажмите **обновить список** и включите **PikoBoard**. Если плагин ещё не появился, перезапустите Obsidian.
3. Нажмите **Cmd/Ctrl+P** → **PikoBoard: Создать доску**, задайте название и папку.
4. Нажмите **+ Задача**, введите название и нажмите **Enter**. Доска готова к работе.

У каждого плагина своя папка: конечный путь — `.obsidian/plugins/pikoboard`, а не сама `.obsidian/plugins`. Имя папки `pikoboard` совпадает с `id` в `manifest.json`. Клон в произвольную папку компьютера не устанавливает плагин в Obsidian. Если у хранилища другая папка конфигурации, замените `.obsidian` в команде на неё. Автоматически включать сторонние плагины за пользователя Obsidian не позволяет.

Готовый `main.js` лежит в репозитории: `npm install` и сборка для установки не нужны. Плагин появится в списке **установленных** плагинов; в общем каталоге сообщества его пока нет.

### Без Git

Скачайте репозиторий через **Code → Download source code → zip**, распакуйте и скопируйте **`main.js`, `manifest.json`, `styles.css`, `LICENSE`, `THIRD-PARTY-LICENSES.txt`** в `.obsidian/plugins/pikoboard/` внутри своего хранилища. Затем обновите список сторонних плагинов и включите PikoBoard.

### Обновление

Для установки клоном:

1. Закройте окна задач и выключите PikoBoard в списке сторонних плагинов.
2. Из папки хранилища выполните:

   ```sh
   git -C .obsidian/plugins/pikoboard pull --ff-only
   ```

3. Включите PikoBoard снова. Пересборка не нужна.

Кнопка Obsidian **«Проверить обновления»** пока не обновляет эту установку из GitLab. Для штатного обновления через каталог Obsidian нужна публикация плагина в каталоге с релизами GitHub ([правила Obsidian](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)).

При ручной установке замените пять файлов из раздела «Без Git». Если папка уже существует, не клонируйте поверх неё.

**Не заменяйте `data.json`**: там порядок карточек, черновики, настройки и корзина комментариев.

Начиная с 0.8 имя папки, ID плагина и служебные маркеры — `pikoboard`. Старые имена и маркеры экспериментальных версий не поддерживаются; это не обновление поверх версии 0.7. При переносе старого хранилища сначала сохраните резервную копию и отдельно перенесите настройки и служебные маркеры записей.

При первом запуске PikoBoard однократно читает настройки хранения установленного TaskNotes, если они есть: папку задач, служебный тег или свойство, имена полей и сроки архивации. Личные заметки при этом не переписываются. После этого TaskNotes можно выключить; его код не используется. Описания и дополнительные свойства задач сохраняются. Эта настройка хранения не преобразует маркеры ранних экспериментальных версий PikoBoard.

Папка новых задач и автоархивация доступны в **Настройки → PikoBoard**. Изменение папки влияет только на новые задачи. В новом хранилище папка по умолчанию — `Задачи`, автоархивация — через 7 дней.

После обновления с 0.8 прежние задачи остаются в **Все задачи**. Новую доску можно создать отдельно и добавить в неё существующие задачи через меню доски.

## Как пользоваться

**Создать доску:** команда **PikoBoard: Создать доску** или правый клик по папке → **Создать доску PikoBoard**. Название задаётся при создании. Файл можно переименовать или переместить обычным способом: связь с задачами сохраняется благодаря постоянному ID.

**Открыть доску:** нажмите её файл в файловом менеджере или команду **PikoBoard: Открыть доску**. Нажатие на название в шапке переключает доски. Команда **PikoBoard: Все задачи** показывает задачи всех досок и задачи без доски в трёх общих столбцах по типу статуса.

**Добавить столбец:** плюс справа от последнего столбца. Введите название, выберите цвет и значок. Значок открывает сетку иконок и эмодзи; пункт «Без значка» убирает его.

**Переставить столбцы:** перетащите заголовок прямо на доске. С клавиатуры: сфокусируйте заголовок и нажмите **Alt+← / Alt+→**. **Esc** отменяет перетаскивание. Порядок сохраняется в файле доски; задачи и их статусы не меняются.

**Настроить и удалить:** `⋯` в шапке доски → **Настройки доски**; то же меню есть у каждого столбца. Здесь меняются название, значок, цвет и прозрачность фона. 100% — прозрачный фон. Корзина удаляет пустой столбец после сохранения; из занятого сначала нужно перенести задачи, включая архивные. Новые столбцы участвуют в обзоре «В работе»; исходный `done` остаётся завершающим независимо от переименования или позиции. Неизвестные статусы отображаются в **Без столбца** и исправляются через карточку.

**Папки:** глобальные пути задаются в **Настройки → PikoBoard**. Отдельные пути для конкретной доски — `⋯` → **Папки доски**. Поля показывают действующую папку; ввод задаёт её только для этой доски, стрелка возврата восстанавливает общую папку. Пустое поле означает корень хранилища. Изменение пути влияет только на новые файлы.

**Перенос задач:** меню задачи → **Перенести на доску**. Через меню доски можно добавить уже существующую задачу без доски. На каждой задаче одна доска и, отдельно, один необязательный проект. Удаление файла доски не удаляет задачи: они остаются в **Все задачи**, откуда их можно перенести на другую доску.

**+ Задача** открывает строку сверху столбца. Enter создаёт задачу; Cmd/Ctrl+Enter создаёт её и открывает окно. Если выбран проект, новая задача наследует его. Название открывает задачу; стрелка справа раскрывает историю на доске.

**Запись** добавляет комментарий: Enter отправляет, Shift+Enter переносит строку. Скрепка прикрепляет материалы. Меню `⋯` позволяет изменить или удалить запись; восстановление доступно сразу после удаления и через команду **PikoBoard: Восстановить удалённую запись**.

**Следующий шаг** заменяет текущий закреплённый текст. Карандаш подставляет его в поле редактирования, крестик снимает закрепление с возможностью отмены. Кнопка **Чеклист** добавляет пункт; Enter продолжает список, Enter на пустом пункте завершает список, Cmd/Ctrl+Enter сохраняет. Отмеченные пункты остаются на месте. Результат работы можно отдельно записать в историю.

**Проекты** определяются свойством `type: project` в заметке. По умолчанию новые проекты создаются в `Проекты/`, исследования — в `Материалы/`, прикреплённые файлы — в `Вложения/`; пути настраиваются. Теги вводятся прямо в карточке: `#пример #ресерч`.

**Архив** скрывает задачу с основной доски, сохраняя файл. PikoBoard проверяет завершённые задачи при открытии хранилища и раз в минуту, пока Obsidian работает. По умолчанию они уходят в архив через 7 дней; срок можно изменить или отключить в настройках. Если Obsidian был закрыт, архивация произойдёт при следующем открытии. Возврат завершённой задачи из архива даёт новый полный срок до архивации. Корзина задачи перемещает её файл в `.trash` хранилища после подтверждения.

## Данные и приватность

Доски и их оформление хранятся в файлах `.pikoboard`. Задачи, описания, история и следующий шаг хранятся в Markdown-файлах текущего хранилища. Начиная с 0.9 свойство `board` в задаче зарезервировано для ID доски; задачи без него остаются в общем обзоре. Порядок карточек, черновики и удалённые комментарии — в `.obsidian/plugins/pikoboard/data.json`. История и шаг отделены служебными HTML-комментариями: не удаляйте эти маркеры вручную.

В PikoBoard нет собственной аналитики, ключей доступа или кода отправки заметок на сервер. Синхронизация определяется настройками Obsidian; внешние ссылки и вложенные ресурсы обрабатываются его Markdown-рендерером и другими установленными плагинами.

Этот репозиторий содержит только код, документацию и искусственные тестовые данные. Файлы хранилища, резервные копии, локальные настройки и импорты в него не входят. Не прикладывайте `data.json`, реальные заметки или скриншоты с личными данными к публичным issues.

## Разработка

Требуется Node.js 18+. Для сборки и тестов нет npm-зависимостей, `npm install` не нужен.

```sh
git clone https://gitlab.com/ksumarshmallow/obsidian-pikoboard.git
cd obsidian-pikoboard
npm test
npm run check
```

- `plugin.js` — интерфейс, настройки и интеграция с Obsidian.
- `board-store.js` — файлы досок, настройки столбцов, стабильные ID и конфликты сохранения.
- `task-store.js` — самостоятельное чтение и атомарная запись задач, совместимость прежних полей и автоархивация.
- `core.js` — работа с Markdown, история, следующий шаг, фильтры и порядок.
- `styles.css` — оформление.
- `build.js` — сборка `main.js`; готовый файл не редактируется вручную.
- `tests/` — автоматические тесты хранения, миграции, архивации, конфликтов сохранения и синхронизации ввода.

После изменения кода выполните `npm test`: команда сначала пересоберёт `main.js`. Для проверки интерфейса используйте отдельное тестовое хранилище.

## Ограничения

- PikoBoard читает задачи с тегом `task` в свойствах заметки; при переходе сохраняет настроенный в TaskNotes способ определения задач. Файлы обычных заметок и проектов не становятся задачами автоматически.
- Календари, тайм-трекинг, повторяющиеся задачи и представления Bases из TaskNotes здесь не реализованы. Существующие дополнительные поля сохраняются, но PikoBoard не выполняет связанную с ними логику.
- На отдельной доске от 1 до 30 столбцов; лишние столбцы прокручиваются горизонтально. Общий обзор объединяет их по типу в три столбца. Блокирующих зависимостей между задачами и совместного редактирования в реальном времени нет.
- Формат доски `.pikoboard` — обычный JSON. Задачи остаются Markdown. Не копируйте файл доски для создания новой: дубликаты одного ID блокируются, чтобы не смешать задачи; создавайте новые доски командой.
- Редактор описания использует внутренний API Obsidian и может потребовать адаптации после обновления приложения. Если загрузить его не удалось, остаётся обычное текстовое поле.
- Интерфейс адаптируется к узкому окну, но на телефоне отдельно не проверен.
- Это ранняя версия. Перед обновлением полезно иметь резервную копию хранилища.
